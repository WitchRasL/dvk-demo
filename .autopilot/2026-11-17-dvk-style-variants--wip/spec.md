# Спецификация: ДВК Стиль — три варианта редизайна с переключением

## Задача

«ДВК Стиль» заказала редизайн dvk-style.ru. Нынешний сайт — шаблон Bitrix: меню на ~200 пунктов капсом, три разных бизнеса свалены в один список, сильные факты (своё производство, полный цикл, клиенты уровня Эрмитажа) спрятаны, нет подбора и запроса КП. Заказчик хочет увидеть **несколько принципиально разных вариантов** нового сайта — живых, с переключением между ними — и выбрать лучший. На главной — hero со скролл-видео премиального интерьера и всплывающими пояснениями; дальше — экраны со scroll-trigger появлением; под всем — понятная структура разделов и товаров, в которую потом переедет каталог dvk-style.ru.

## Решение

Один сайт-прототип, три варианта: «Шоурум», «Палитра RAL», «Чертёж». Плавающий переключатель на каждой странице меняет вариант и оставляет посетителя на той же странице — сравнивать можно один к одному. Структура разделов, каталог, данные, запрос КП и квиз — общие; у каждого варианта своя главная, свой визуальный мир (шрифты, цвет, карточка товара, анимации) на всех страницах и своя главная «фишка». В hero каждого варианта — движок скролл-видео: пока ролика нет, работает заглушка (реальное фото проекта ДВК, по которому камера движется при скролле); готовый ролик подставляется одним файлом. Под каждый вариант — раскадровка и промпт для генерации ролика. Контент и фото — реальные, с dvk-style.ru; чего нет — видимая заглушка `[уточнить]`.

## Три варианта

Тексты и правила вариантов — для исполнителей; на сайте каждый вариант описан в панели переключателя (R24).

### V1 «Шоурум» (`showroom`) — закреплён брифом (R27)
- **Мир:** тёмный шоурум ДВК ночью; единственный источник тепла — свет витрин; латунь, стекло, тёплый камень. Развивает `references/a9d1f60f7f504236b9873fc0bb4f2130.jpg`.
- **Палитра:** почти чёрный графит с тёплым оттенком как фон; латунь/золото — только там, где свет (кнопка заявки — градиентная золотая, R27); камень/крем — подиумы под фото товаров (R36).
- **Шрифты:** Tenor Sans (заголовки), PT Serif Italic (одно слово-акцент в заголовке), Golos Text (текст). Все — `@fontsource`, кириллица.
- **Фишка «Включи витрину» (R22):** в hero и в bento-каталоге подсветка зажигается по скроллу; курсор — луч света (светлое пятно-слой, двигается `transform`, R57). Мобильная версия: подсветка зажигается по скроллу, без курсора; reduced-motion — всё сразу освещено.
- **Крошки «ПРОЕКТИРОВАНИЕ / ПРОИЗВОДСТВО / МОНТАЖ» (R27):** текст и вид как в референсе — три слова капсом через слэш, мелко. Место — строка в hero, но не надпись прямо над заголовком (eyebrow запрещён craft-floor): строка работает индикатором хода hero-ролика — слово загорается, когда ролик проходит свою фазу; клик перематывает к ней.
- **Bento-каталог (R27, R19):** три направления — плитки равного веса (направления равноправны); внутри направления разделы — плитки разного размера; Spotlight-рамка от курсора; магнитная кнопка заявки.
- **Направления (R18):** ритейл — тёплый LED; благоустройство — сумерки и фонари; металл — холодный боковой свет с тёплым бликом. Шапка, шрифты, сетка, кнопки — общие для варианта.
- **Моушн:** «свет включается»: opacity + clip-path круга от точки, ease-out 600–900 мс.

### V2 «Палитра RAL» (`ral`)
- **Мир:** веер порошковых красок RAL, которыми ДВК красит металлическую мебель и площадки. Цвет — целыми полями (стратегия Drenched/Committed), а не акцентами.
- **Палитра:** направление = свой RAL целым полем: благоустройство — сочный жёлто-зелёный/жёлтый площадок; металл — RAL 7035 светло-серый со сталью; ритейл — графит/RAL 9005 с тёплым светом. Сигнальный оранжевый (класс RAL 2004) — **только** у заявки: кнопка «Заявка на подбор», отправка квиза (раз из «creator-hardware»: одна сигнальная клавиша на то, что важно). «В запрос КП» на карточках — не оранжевая. Конкретные коды — решение исполнителя, но каждый образец подписан своим кодом.
- **Шрифты:** Unbounded (заголовки), Onest (текст), JetBrains Mono (коды RAL, артикулы, габариты — это данные, не костюм).
- **Фишка «Веер направлений» (R22):** веер из трёх больших образцов; выбор образца перекрашивает весь сайт (заливка цветом по `clip-path`) и ведёт в направление. Мобильная версия: веер — горизонтальный scroll-snap образцов; reduced-motion — мгновенная смена без заливки.
- **Сетка:** модуль 600 мм — раскладки ложатся целыми модулями (раз из «azulejo»: целые плитки, не доли). Карточка товара — образец с единой сеткой подписи: название · RAL/материал · габариты · артикул (раз из «sneaker-box»: одна сетка этикетки правит каждую карточку).
- **Направления (R18):** меняется поле цвета; шапка, шрифты, сетка общие.
- **Моушн:** шторки цвета (clip-path inset), шаг целыми модулями; кинетическая типографика заголовка hero (R19).

### V3 «Чертёж» (`blueprint`)
- **Мир:** лист рабочей документации по ЕСКД: светлый лист, рамка формата с зонами, основная надпись (штамп), выносные и размерные линии, спецификация. Риск честно назван: чертёжная эстетика — известный приём «инженерных» сайтов; держим её строгостью ГОСТа, а не синькой.
- **Палитра:** светлый лист (не крем), чёрные линии по толщинам ЕСКД; один цвет-маркер для LED/подсветки и действия.
- **Шрифты:** Fira Sans Condensed (заголовки, курсив — отсылка к чертёжному шрифту), Fira Sans (текст), PT Mono (размеры, артикулы, номера листов).
- **Фишка «Режим чертёж» (R22):** на карточке и странице товара фото переключается в чертёж: SVG-шаблон по типу изделия (витрина, прилавок, шкаф, стеллаж, верстак, скамейка, элемент площадки) со слоями **каркас**, **стекло** (если в материалах есть стекло), **LED** (если подсветка не `none`) и **размеры** (из данных товара, нет данных — `[уточнить]`). Desktop — наведение/ползунок; мобильная — тап-переключатель; reduced-motion — без анимации перехода.
- **Hero:** пояснения — выноски с полкой и размерным/техническим текстом (габарит, материал, подсветка — из данных, иначе `[уточнить]`).
- **Каталог как спецификация:** в V3 список товаров в каталоге — таблица-спецификация (поз., обозначение/артикул, наименование, габариты, материал, кол-во в КП), а не сетка карточек; на мобильном строки складываются в компактные блоки.
- **Навигация листами:** каждый экран главной — «Лист N из M» в штампе; штамп в углу показывает текущий раздел. Номера листов несут информацию (где ты в документе), поэтому разрешены.
- **Направления (R18):** тип листа: ритейл — фасады и узлы витрин; благоустройство — генплан; металл — деталировка и нагрузки.
- **Моушн:** линии «вычерчиваются» через clip-path-шторку (не stroke-dashoffset — R57), выноски выезжают от точки.

## Экраны главной (R09, R10)

Каждый вариант собирает главную из этих экранов в своём порядке и форме (6–8 экранов; вайрфрейм в панели переключателя — 6–8 блоков в одну строку через `→`). Направления равноправны: выход в три направления есть уже в первом экране (три равных ссылки поверх hero), экран «Выбор направления» раскрывает их. Исполнитель фиксирует итоговый список с анимациями в `docs/variants/<id>.md` — это и есть предложение пользователю «какие экраны и элементы».

| Экран | Что на нём (факты ДВК) | Scroll-trigger |
|---|---|---|
| Hero — скролл-видео | позиционирование за 5 секунд (R13), главное действие «Заявка на подбор» + телефон (R14), всплывающие пояснения деталей интерьера (R08) | ролик идёт по скроллу; пояснения появляются и уходят на своих отрезках |
| Выбор направления | три направления с разделами и числом товаров (R11, R15) | V1 плитки зажигаются; V2 веер раскрывается; V3 спецификация заполняется строками |
| Полный цикл | замер (выезд бесплатный) → проект → своё производство → доставка своим транспортом → монтаж и такелаж | шаги по очереди при прокрутке (закреплённая секция) |
| Решения по отраслям | аптеки (12 серий), ювелирные, оптика, музеи, одежда/обувь, островки ТЦ, дворы и школы, склады и цеха | интерактивные табы (R19), смена картинки |
| Каталог-витрина | 6–9 характерных товаров с «Добавить в запрос КП» | карточки появляются группой, не по одной одинаково |
| Проекты | 3–6 реальных проектов с фото | V1 подсветка, V2 цветные плашки, V3 листы |
| Клиенты и благодарности | 10 клиентов (названия/логотипы с сайта), благодарственные письма | спокойный экран, минимум движения |
| Госзаказ и тендеры | работа с госзаказами, ТЗ к тендерам, брендирование | — |
| Заявка | квиз подбора (R53) или вход в него + контакты двух городов | — |

Ритм: плотный экран сменяется спокойным; одно авторское движение на экран, не одинаковый fade-up везде (craft-floor).

## Решения по реализации

- **Один SPA, вариант — первый сегмент пути** (`/#/<variant>/…`). Почему: сравнение одной и той же страницы в трёх вариантах — это смена одного сегмента; общие данные и логика не дублируются.
- **Общее ядро + кожа варианта.** Ядро (`src/core/`) владеет данными, каталогом, КП, городом, квизом, скролл-видео и структурой внутренних страниц. Вариант (`src/variants/<id>/`) владеет токенами, шрифтами, шапкой, футером, главной, карточкой товара, кнопкой, заголовком секции, шапкой внутренней страницы и CSS-переопределениями внутренних страниц. Почему: «своя главная + свой стиль везде» без трёх копий каталога и квиза.
- **Токены — CSS-переменные на `[data-variant]`, отображённые в Tailwind `@theme`.** Внутренние страницы пишутся классами на токенах (`bg-bg`, `text-fg`, `font-display`) и автоматически перекрашиваются; вариант дополнительно правит их своим CSS. Направление — `[data-direction]` поверх токенов варианта.
- **Варианты грузятся лениво**: `import()` по id; шрифты и CSS варианта импортируются в его модуле. Почему: Performance ≥ 85 — посетитель V1 не качает шрифты V3.
- **Скролл-видео:** закреплённая сцена, прогресс → `currentTime` через rAF со сглаживанием; ролик ожидается с ключевым кадром на каждом кадре (`ffmpeg … -g 1`), иначе перемотка дёргается — инструкция в `docs/hero-video/README.md`. Нет файла / ошибка загрузки → режим заглушки. Почему не секвенция кадров: заказчик подставляет «один файл».
- **Квиз и КП — без бэкенда.** Отправка — адаптер: нет `VITE_FORM_ENDPOINT` → демо; есть → `POST` `multipart/form-data` с `Accept: application/json` (совместимо с Formspree и Web3Forms). Ключей в коде нет; имя переменной — в `.env.example`.
- **Данные** — четыре JSON из R32; отрасли, алиасы старых названий и серии аптек — внутри `categories.json` и `company.json`. Картинки — `public/images/<products|projects|company>/<slug>/<n>-{800,1600}.webp`, UI строит `srcset` сам.
- **Тесты:** Vitest для логики ядра (каталог, URL-параметры, КП, квиз, телефон, отправка, прогресс видео). UI проверяется сборкой и скриншотами.
- **Дизайн-качество (R05):** исполнители поверхностей читают `.claude/skills/impeccable/reference/craft-floor.md` и `mode-persuade.md` и свой direction contract (`.impeccable/surfaces/`); после сборки — детектор `impeccable detect` и финальное дизайн-ревью каждого варианта (impeccable-finish-reviewer).
- **Общение с пользователем (R69):** по-русски и коротко; между этапами без пересказа; каждый этап кончается ясно — что готово и что нужно от пользователя.
- **Без сторонних встраиваний:** карт и виджетов нет — ссылка «открыть в Яндекс Картах» вместо встройки. Почему: Performance и noindex-концепт.
