## Что должно заработать

В `src/data/` лежат настоящие данные с dvk-style.ru: дерево категорий с числом товаров и чистыми названиями, 30–40 характерных товаров (по 8–12 на направление: ритейл, благоустройство, металл), 5–10 проектов с фото, сведения о компании (полный цикл, услуги, клиенты, благодарственные письма, контакты двух городов, реквизиты, серии аптек, год основания — если найден). Фото скачаны вежливым скриптом в WebP 1600/800 с манифестами источников. Чего нет на сайте — `[уточнить]` и строка в `docs/todo-utochnit.md`.

## Как собирать

Сеть открыта (dvk-style.ru отвечает 200, `/upload/` не закрыт в robots.txt). Сбор страниц — скриптом на Node (`cheerio`) в `scripts/collect/` с той же вежливостью (пауза 0,5–1 с, robots.txt, кэш HTML в `scripts/collect/.cache/`; верни этот путь в отчёте — оркестратор добавит его в `.gitignore`). Выбирай товары с хорошими фото и полными характеристиками, разных категорий. Для `heroPhotos` в `company.json` отбери 3–6 лучших фото интерьеров из проектов (по одному-два на направление): это заглушки hero. Если на момент сбора сеть из shell закроется — тексты через веб-инструмент, фото — команда `npm run fetch-images` для пользователя; скажи об этом в отчёте.

## Критерии приёмки

- [ ] `categories.json`: 3 направления → разделы → категории с числом товаров с сайта и `sourceUrl`; названия без капса и хвостов поставщиков («промет», «диком», «версия»), дубль «Промышленная мебель»/«Металлическая мебель» слит; старые названия — в `aliases`; отрасли (`industries`) с `pharmacy` и её сериями (названия и фото с сайта)
- [ ] `products.json`: 30–40 товаров, по 8–12 на каждое направление; у каждого все поля схемы `interfaces.md`, `sourceUrl`, цена или `priceNote: 'по запросу'`, `kind`; ни одной выдуманной характеристики
- [ ] `projects.json`: 5–10 проектов с фото и `sourceUrl`
- [ ] `company.json`: полный цикл (5 шагов), услуги (брендирование, госзаказ, ТЗ к тендерам), обещание (бесплатный подбор, ответ за 2 часа), позиционирование, клиенты (логотипы, если есть на сайте), благодарственные письма (фото/скан и источник), контакты СПб и Москвы, реквизиты, год основания — проверен на странице «О компании», `heroPhotos`
- [ ] `scripts/fetch-images.mjs` на sharp: берёт только оригиналы `/upload/iblock/…`, пауза 0,5–1 с, проверяет robots.txt, не качает уже скачанное; пишет `<n>-1600.webp` и `<n>-800.webp`, `manifest.json` рядом с фото каждого товара/проекта и общий `public/images/manifest.json` с исходными URL; запускается `npm run fetch-images`
- [ ] Фото реально скачаны, все пути `images[].base` из JSON указывают на существующие файлы (проверка тестом)
- [ ] `docs/todo-utochnit.md` — список всех мест `[уточнить]` с тем, что нужно от заказчика; `docs/content-sources.md` — откуда что взято
- [ ] Тест: JSON валидны по схеме (обязательные поля, направления из трёх id, уникальные slug, ссылки категорий товаров существуют)
