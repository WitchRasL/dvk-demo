## 3. Тематические «фишки»

Это банк идей. Каждый концепт берёт одну главную «фишку».

- **«Включи витрину».** Hero — тёмный шоурум. При загрузке и скролле зажигается подсветка витрин, курсор работает как луч света.
- **Конструктор прилавка или витрины.** Пользователь выбирает тип, ширину, подсветку (тёплая или холодная) и материал (металл, стекло, ЛДСП, дерево). Живое SVG-превью собирает бриф и отправляет его в заявку.
- **Планировщик зала или островка в ТЦ.** Сетка-план, модули перетаскиваются мышью, считаются площадь и ширина прохода. Результат уходит в заявку.
- **Режим «чертёж».** При наведении фото товара превращается в blueprint: видны каркас, стекло, LED и размеры.
- **До/после.** Шторка «пустое помещение → готовый магазин» на реальных проектах.
- **День/ночь во дворе.** Для направления «Благоустройство»: площадка днём превращается в вечернюю, с фонарями.
- **Калькулятор нагрузки.** Для верстаков и стеллажей: пользователь выбирает серию (до 400 / 500 / 1000 / 1500 / 3000 кг), анимированная полка держит груз или прогибается.
- **Карта объектов.** Россия с точками проектов и клиентов, фильтр по направлению.
- **Переключатель направлений.** Одно движение переключает тему всего сайта (Ритейл ↔ Благоустройство ↔ Металл) с анимированной сменой света.

### ЭТАП 4 — сборка проекта

#### Стек

| Задача | Инструмент |
|---|---|
| Основа | React + Vite |
| Стили | Tailwind CSS v4 (`@tailwindcss/vite`), токены Nocturne в `@theme` |
| Анимация | Motion — бывший Framer Motion: пакет `motion`, импорт из `motion/react` |
| Иконки | Lucide React |
| Маршрутизация | React Router (HashRouter) |
| Шрифты | локально через `@fontsource`: Cormorant Garamond, Manrope (с кириллицей) |

GSAP и Lenis подключай, только если без них не получается «фишка».

#### Страницы (MVP)

1. **Главная** — по выбранному концепту.
2. **Каталог** — направления → категории.
   - Фильтры: направление, отрасль, категория, материал, подсветка, поиск. Фильтры синхронизируются с URL.
   - Сортировка и быстрый просмотр товара.
3. **Карточка товара** — галерея, характеристики, кнопка «Добавить в запрос КП», похожие товары, блок «Как мы работаем».
4. **Решение для отрасли** — на примере «Аптеки» с сериями; это шаблон для остальных отраслей.
5. **Проекты** — галерея и страница кейса.
6. **О компании / Производство** — полный цикл, клиенты, благодарственные письма, сертификаты (если они есть на сайте).
7. **Контакты** — Санкт-Петербург и Москва, переключатель города в шапке.

#### Ключевые механики

- **«Запрос КП» вместо корзины.** Товары копятся в подборке (localStorage) и уходят в форму списком.
- **Форма заявки / квиз подбора.**
  - 3–4 шага: направление → объект → сроки → контакты.
  - Маска телефона +7, согласие на обработку ПД (152-ФЗ), прикрепление плана помещения (необязательно).
  - Бэкенда нет, поэтому по умолчанию форма работает в демо-режиме и показывает экран успеха.
  - Реальная отправка идёт через `VITE_FORM_ENDPOINT` (Formspree или Web3Forms). Она выключена, пока заказчик не подключит свой адрес. Токены ботов во фронтенд не класть.
- **«Фишка» выбранного концепта** работает полноценно. У неё есть упрощённая мобильная версия и вариант для `prefers-reduced-motion`.
- **Анимации** — по разделу 9 Nocturne:
  - easing и длительности берутся из токенов;
  - анимируются только transform, opacity и clip-path;
  - фото в hero видно с первого кадра.

#### Качество

- **Адаптив:** 360 / 768 / 1024 / 1440. На мобильном карточки идут горизонтальным scroll-snap.
- **Lighthouse (mobile):** Performance ≥ 85, Accessibility ≥ 95.
- **Производительность:** код разделён по маршрутам; у фото `loading="lazy"` и `srcset`.
- **Доступность:** семантичная разметка, стили фокуса, alt-тексты из названий товаров.
- **Пути к картинкам** — через `import.meta.env.BASE_URL`, иначе на GitHub Pages они сломаются.
- **Пометка концепта.** Это концепт, а не официальный сайт, поэтому:
  - в футере стоит пометка «Концепт редизайна dvk-style.ru»;
  - в `<head>` стоит `<meta name="robots" content="noindex, nofollow">`;
  - в `robots.txt` стоит `Disallow: /`.

  Так копия не попадёт в поиск и не будет конкурировать с живым сайтом.

Шаблон `deploy.yml`. Версии экшенов указаны минимальные рабочие, можно новее.

```yaml
name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```
