## Что должно заработать

Логика, на которой стоят все страницы и варианты: запрос к каталогу с фильтрами, поиском, сортировкой, пагинацией и синхронизацией с URL; подборка «Запрос КП» в localStorage; выбор города; квиз заявки (шаги, черновик, валидация телефона и файла, отправка через адаптер с демо-режимом); движок скролл-видео с режимами video / placeholder / static, пояснениями и фазами. Всё покрыто тестами на фикстурах (не на реальных JSON — их параллельно заполняет T02).

## Из брифа, дословно

> «Главная hero-секция должна иметь скролл-триггер-анимацию, где у нас впоследствии будет сгенерирован премиальный интерьер, в качестве которого будет видео - сгенерированная анимация, которая будет проигрываться в процессе скроллинга. При скроллинге также на видео будут появляться всплывающие элементы пояснения некоторых деталей.»
> «Каталог — направления → категории. Фильтры: направление, отрасль, категория, материал, подсветка, поиск. Фильтры синхронизируются с URL. Сортировка и быстрый просмотр товара.»
> ««Запрос КП» вместо корзины. Товары копятся в подборке (localStorage) и уходят в форму списком.»
> «3–4 шага: направление → объект → сроки → контакты.» · «Маска телефона +7, согласие на обработку ПД (152-ФЗ), прикрепление плана помещения (необязательно).» · «по умолчанию форма работает в демо-режиме и показывает экран успеха» · «Реальная отправка идёт через `VITE_FORM_ENDPOINT` (Formspree или Web3Forms). Она выключена, пока заказчик не подключит свой адрес. Токены ботов во фронтенд не класть.»
> «Контакты — Санкт-Петербург и Москва, переключатель города в шапке.»
> «анимируются только transform, opacity и clip-path»
> Дополнение: «пока ролика нет — заглушка: кадр-референс, по которому камера движется при скролле; готовый ролик подставляется одним файлом»

## Критерии приёмки

- [ ] `queryProducts` фильтрует по направлению, разделу, категории, отрасли, материалу, подсветке; поиск без регистра, ё = е; сортировка; страницы по 24; фасеты со счётчиками считаются из данных
- [ ] `parseCatalogParams`/`toSearchParams` — обратимы; мусорные и неизвестные значения отбрасываются без ошибки; `useCatalogQuery` пишет фильтры в URL и читает их обратно
- [ ] `kpReducer` + `useKp`: add/remove/setQty/clear, количество ≥1, переживает перезагрузку (localStorage `dvk-kp-v1`), без localStorage работает в памяти; товар, исчезнувший из данных, отдаётся с `product: null`
- [ ] `useCity`: `spb`/`msk`, по умолчанию `spb`, запоминается; отдаёт контакты из `company.json`
- [ ] `formatPhone` даёт `+7 (XXX) XXX-XX-XX` по мере ввода (8 и 7 в начале → +7); `isPhoneComplete`; `validateContacts` — тексты ошибок по-русски; без согласия — ошибка
- [ ] `validateFile`: до 10 МБ, pdf/jpg/png/dwg, иначе понятная ошибка; файл необязателен
- [ ] `quizReducer`/`useQuiz`: 4 шага, назад/вперёд, черновик в localStorage `dvk-quiz-v1` восстанавливается; повторная отправка во время отправки невозможна
- [ ] `submitRequest`: без endpoint → `{ ok: true, demo: true }` и ничего не уходит в сеть; с endpoint → `POST` `multipart/form-data`, `Accept: application/json`, список КП и файл; не-2xx/сеть → `{ ok: false, error }`; тесты с подменённым `fetchImpl`
- [ ] `ScrollVideo`: закреплённая сцена, прогресс скролла → кадр ролика (rAF + сглаживание); нет файла или ошибка → режим `placeholder` (фото с движением камеры `camera.from → to` и пометкой «Здесь будет видео-интерьер»); `prefers-reduced-motion` → `static` без закрепления; пояснения появляются на своих отрезках и всегда есть упорядоченным списком для скринридера; `phases` и `seekTo` для индикаторов; анимируются только transform/opacity/clip-path; постер виден с первого кадра
- [ ] Демо-страница движка `/#/<variant>/__scroll-video` (только в dev) показывает все три режима на фикстуре
- [ ] `docs/hero-video/README.md`: куда положить `hero.mp4` (и `hero-mobile.mp4`), команда перекодирования `ffmpeg … -g 1 -crf 22 -an -movflags +faststart`, рекомендуемые размеры и длительность, как проверить
- [ ] Тесты: `progressToTime`, `calloutState`, `phaseAt` и все швы из `interfaces.md` зелёные
