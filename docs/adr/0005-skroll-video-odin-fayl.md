# Скролл-видео: один файл, перемотка по currentTime, заглушка

## Контекст
Hero каждого варианта — ролик премиального интерьера, который идёт по скроллу, с пояснениями на отрезках (R06–R08). Ролики генерирует заказчик (позже, через Higgsfield), а в сборке пока их нет; заменить заглушку надо без правки кода (R71i).

## Решение
Закреплённая сцена; прогресс скролла переводится в `currentTime` одного видеофайла через rAF со сглаживанием. Ролик ожидается с ключевым кадром на каждом кадре (`ffmpeg … -g 1`), есть необязательная мобильная версия. Три режима: `video` (файл загрузился), `placeholder` (файла нет или ошибка: реальное фото проекта с движением камеры) и `static` (`prefers-reduced-motion`: без закрепления, кадр и список пояснений). Пояснения всегда дублируются упорядоченным списком для скринридеров.

## Почему
- Отвергнуто: секвенция кадров. Заказчик должен подставить один файл, а не папку из сотен картинок.
- Без ключевого кадра на каждом кадре перемотка дёргается; цена — больший размер файла.
- Режим-заглушка нужен, чтобы hero не был пустым, пока ролика нет.

## Последствия
- Ролик обязан быть перекодирован под покадровую перемотку (инструкция в `docs/hero-video/README.md`); обычный mp4 заказчика будет дёргаться.
- Файл больше обычного видео — давление на Performance на медленной сети, поэтому первый кадр (постер) показывается сразу, а ролик догружается.
- Варианты стилизуют сцену только через контракт классов ядра; своих классов вне контракта и своих медиазапросов у них быть не должно.
