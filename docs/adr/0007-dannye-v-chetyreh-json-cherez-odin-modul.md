# Данные — четыре JSON, читаются через один модуль

## Контекст
Сейчас нужны 30–40 реальных товаров, но потом переедет примерно 4 000 позиций с текущего сайта на Битрикс (R12, G02). Источник данных поменяется, а доступа к Битрикс заказчика пока нет.

## Решение
Данные лежат в `categories.json`, `products.json`, `projects.json`, `company.json`. Схема повторяет дерево dvk-style.ru (id, slug, sourceUrl, число товаров на сайте) и содержит таблицу алиасов старых названий. Все читают данные только через `src/core/catalog`; фасеты считаются из данных, каталог листается по 24 с `page` в URL. Для подключения к Битрикс рекомендован путь 2 из `docs/bitrix-integration.md` — данные при сборке.

## Почему
- Отвергнуто: читать JSON напрямую из страниц. Замена источника потребовала бы правки каждой страницы; единственный модуль даёт одно место замены.
- Отвергнуто: хардкод списков фильтров. Он не выдерживает рост с 40 до 4 000 позиций (R12.1).
- Отвергнуто: подключать Битрикс сейчас. Нет доступа и способа выгрузки; решение отложено (G02).
- Конкретные альтернативы подключения разобраны в записке для заказчика, здесь они не повторяются.

## Последствия
- Числа у разделов (408, 1133…) — товары на dvk-style.ru, в прототипе их 35; интерфейс обязан говорить это словами, иначе числа обманывают.
- Неизвестные факты остаются видимой заглушкой `[уточнить]` (R37); год основания и число лет расходятся на сайте и стоят `null`.
- Схему на этапе полного сайта придётся расширять (например, `externalId`, `oldprice`), и это затронет все три варианта сразу.
