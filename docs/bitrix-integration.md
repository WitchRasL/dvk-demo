# Каталог из 1С-Битрикс на новом сайте: как подключить

Записка для заказчика и разработчика. Проверено 18.11.2026 по публичным страницам dvk-style.ru (главная, раздел `/catalog/aptechnye-prilavki/`, товар `/catalog/aptechnye-prilavki/kassovyy-prilavok-malyy/`, `robots.txt`, `sitemap.xml`) и двум публичным XML-файлам, которые сам `robots.txt` разрешает. Админка не открывалась, формы не отправлялись. То, что без доступа узнать нельзя, помечено `[уточнить]`.

## Что видно снаружи

| Куки `PHPSESSID`, в HTML `BX.*`, `bitrix_sessid`, `JCCatalogItem` | главная, раздел, товар |
| Шаблон `/bitrix/templates/business_v…`; компоненты `/bitrix/components/alexkova.business…` (стороннего разработчика) | главная |
| Фото: оригиналы `/upload/iblock/…` и `/upload/medialibrary/…`, превью `/upload/resize_cache/…` | все страницы |

| **Публичная выгрузка YML есть.** `robots.txt` закрывает `/bitrix/`, но явно разрешает два файла | см. ниже |

Выгрузки в `/bitrix/catalog_export/`:

| Файл | Товаров | Разделов | Размер | Дата внутри файла |
|---|---|---|---|---|
| `export_market.xml` | 303 | 37 | 640 КБ | 23.03.2023 |
| `export_discount.xml` | 1912 | 127 | 4,4 МБ | 14.07.2023 |

Состав товара в YML: `id`, `url`, `name`, `price`, `oldprice` (только в `export_discount`), `categoryId`, несколько `picture` (оригиналы), `description` (HTML), набор `param name="…"`. Нет артикула, остатков, `vendor`. Файлы не пересекаются (3 общих `id`) и вместе покрывают не весь каталог: из 35 товаров прототипа в них есть 22. Цена 11260 на странице совпала с `price` в файле — одна проверка, не гарантия. На сервере у обоих файлов `Last-Modified` — 23.12.2024: обновляются ли они по расписанию, `[уточнить]`.

**Узнать без доступа нельзя** `[уточнить]`: редакцию и версию Битрикс; установлен ли «Торговый каталог» (строка `platform` в YML — `BSM/Yandex/Market`, то есть профиль экспорта Битрикс, но это косвенный признак); коды свойств инфоблока; включён ли REST и CORS; кто администрирует сайт; нужны ли новому сайту остатки, корзина, личный кабинет.

## Три пути

| | 1. Дизайн как шаблон в Битрикс | 2. Отдельный фронтенд, данные при сборке | 3. Отдельный фронтенд, запросы на лету |
|---|---|---|---|
| Как работает | Новый дизайн верстается как шаблон сайта (`/local/templates/…`); каталог, корзина, формы остаются родными | Скрипт забирает YML / CommerceML / REST по расписанию, пишет `src/data/*.json`, сайт пересобирается | Браузер (или наш прокси) запрашивает JSON из Битрикс: REST или свой адрес; ответы кэшируются |
| Нужно от заказчика | Доступ к тестовой копии сайта и репозиторию шаблона, редакция, исполнитель на PHP | Подтвердить, что `/bitrix/catalog_export/` живёт и по расписанию; для полного каталога — вебхук REST или выгрузка CommerceML | Включить REST или написать свой адрес, CORS для нового домена, лимиты нагрузки |
| Плюсы | Каталог, URL и SEO не переезжают; остатки и корзина работают | Быстрый и дешёвый хостинг; падение Битрикс не роняет сайт; код `src/core` почти не меняется | Данные всегда свежие |
| Минусы | React-прототип как код не переиспользуется (токены, вёрстка и тексты — да); шаблон сейчас на сторонних компонентах `alexkova.business` `[уточнить]` лицензию и правки | Данные устарели до следующей пересборки; YML неполный (нет товаров «по запросу»); ~4000 товаров — файл придётся делить на части | Страницы Битрикс отдаются с `Cache-Control: no-store` — нагрузка и задержки на Битрикс; ключ вебхука нельзя класть в браузер (нужен прокси); `data.js` и ядро каталога синхронные — переписывать на асинхронное; поиск и фильтры на сервере |
| Когда брать | Сайт целиком остаётся на Битрикс, есть кому его сопровождать | Каталог меняется редко (раз в день и реже), нужна скорость | Нужны живые остатки и цены |

**Рекомендация.** По умолчанию — путь 2: стартовать на уже открытых YML без доступа к админке, затем перейти на REST или CommerceML ради полного каталога и товаров «по запросу». Он совпадает с тем, как прототип уже устроен, и не требует вмешательства в Битрикс. Выбор зависит от ответов заказчика: (а) если сайт должен остаться на Битрикс с корзиной и кабинетом, а исполнитель на PHP есть — путь 1; (б) если нужны живые остатки — путь 3 (с прокси); (в) редакция Битрикс и наличие «Торгового каталога» решают, доступны ли REST и CommerceML. Для путей 2 и 3 отдельно решается индексация: прототип на `HashRouter` и закрыт от поисковиков, рабочему сайту нужна предварительная генерация страниц и переадресация старых адресов.

## Поле Битрикс → наша схема

Левый столбец — стандартные поля Битрикс; «YML» — что проверено в выгрузке; коды свойств (`PROPERTY_*`) без доступа неизвестны.

| Наша схема | YML (проверено) | Поле Битрикс |
|---|---|---|
| `id` | `offer id` (совпадает ли с `ID` элемента — `[уточнить]`) | `ID` — в схеме поля для него нет, добавить `externalId` |
| `slug` | последний сегмент `<url>` | `CODE` |
| `name` | `<name>` | `NAME` |
| `sourceUrl` | `<url>` | `DETAIL_PAGE_URL` |
| `categoryId`, `sectionId` | `<categoryId>` → имена разделов в YML совпадают с `aliases` (37 из 37; 113 из 127 — остальные отличаются написанием) | `IBLOCK_SECTION_ID` |
| `direction` | нет | считается по разделу (`catalog-map.mjs`) |
| `description` | `<description>` — HTML, у нас обычный текст | `DETAIL_TEXT` / `PREVIEW_TEXT` `[уточнить]` |
| `specs[{label,value}]` | `<param name value>` — один к одному | `PROPERTY_*` `[уточнить]` коды |
| `dimensions`, `load`, `materials`, `lighting` | нет | считаются из `specs` (`collect.mjs`) |
| `industries`, `kind` | нет | редакторские, не из Битрикс: таблица в репозитории или свойство инфоблока `[уточнить]` |
| `price` | `<price>` — текущая цена | цена из «Торгового каталога», тип цены `[уточнить]` |
| `priceNote: 'по запросу'` | нет: в YML у всех товаров есть цена | остаётся для товаров без цены; только REST/CommerceML |
| `images[].base`, `w`, `h` | `<picture>` — оригиналы `/upload/iblock/…` | `DETAIL_PICTURE` + свойство доп. фото `[уточнить]` |
| `images[].alt` | нет | `NAME` товара |
| Раздел: `id`, `name`, `slug`, `parent` | `<category id parentId>` — только id, родитель, имя | `ID`, `NAME`, `CODE`, `IBLOCK_SECTION_ID` |
| Раздел: `count`, `sourceUrl` | нет | `count` считается при импорте; `SECTION_PAGE_URL` |
| Старая цена `oldprice` | есть в `export_discount.xml` | в схеме нет: добавить, если нужна |

## Что нужно от заказчика

- Ответы: редакция и версия Битрикс; установлен ли «Торговый каталог»; кто и где администрирует сайт; нужны ли остатки, корзина, личный кабинет.
- Подтверждение, что `/bitrix/catalog_export/` создан и обновляется по расписанию; какой профиль выгружает весь каталог.
- Список свойств инфоблока каталога (коды и названия), тип цены, где лежат дополнительные фото.
- Для REST: входящий вебхук с правом только на чтение каталога; адрес — в переменной `BITRIX_WEBHOOK_URL`. Для путей 1 и 3 также доступ к тестовой копии сайта (`BITRIX_STAGING_URL`) и разрешение CORS для домена нового сайта. Значения передаются защищённым каналом, в репозиторий не попадают; в `.env.example` — только имена.
- Решение, как переедет SEO: сохраняем адреса `/catalog/…` или настраиваем переадресации.
