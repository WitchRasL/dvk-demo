# Hero-ролик: куда положить, как перекодировать, как проверить

Hero каждого варианта — закреплённая сцена: ролик перематывается скроллом (`src/core/scroll-video/`).
Пока файла нет, на его месте заглушка: постер с движением камеры и пометка «Здесь будет видео-интерьер».
Положили файл — ролик заработал без правки кода.

Ролики трёх вариантов уже лежат в `public/media/<вариант>/`: `hero.mp4`, `hero-mobile.mp4`, `hero-poster.jpg`.
Команда кодирования из раздела «Как перекодировать» прогнана на них (ffmpeg 9.0.2). Заглушка выше — запасное
поведение на случай, если файл не найден или не открылся.

## Куда положить

| Вариант | Основной файл | Для телефона (необязательно) |
|---|---|---|
| Шоурум | `public/media/showroom/hero.mp4` | `public/media/showroom/hero-mobile.mp4` |
| Палитра RAL | `public/media/ral/hero.mp4` | `public/media/ral/hero-mobile.mp4` |
| Чертёж | `public/media/blueprint/hero.mp4` | `public/media/blueprint/hero-mobile.mp4` |

Пути задаются в `heroConfig.sources` варианта (`media/<вариант>/hero.mp4`, `media/<вариант>/hero-mobile.mp4`). На телефоне (ширина до 767 px) сначала берётся
`hero-mobile.mp4`; нет его или не открылся — `hero.mp4`. Нет и его — заглушка. Раскадровка, промпт и опорный
кадр для генерации — в `docs/hero-video/<вариант>.md`; опорный кадр совпадает с постером заглушки.

## Как перекодировать

Каждый кадр ролика должен быть ключевым (`-g 1`): иначе браузеру приходится восстанавливать кадр от далёкого ключевого,
и перемотка скроллом дёргается.

```
ffmpeg -i source.mp4 -vf "scale=1280:-2,fps=24" -c:v libx264 -profile:v high -pix_fmt yuv420p \
  -g 1 -crf 22 -an -movflags +faststart public/media/<вариант>/hero.mp4
```

Для телефона — то же, поуже и с другим `crf`:

```
ffmpeg -i source.mp4 -vf "scale=720:-2,fps=24" -c:v libx264 -profile:v high -pix_fmt yuv420p \
  -g 1 -crf 26 -an -movflags +faststart public/media/<вариант>/hero-mobile.mp4
```

- `-g 1` — все кадры ключевые · `-crf 22` — качество (больше число — меньше файл) · `-an` — без звука ·
  `-movflags +faststart` — метаданные в начале файла, браузер начинает без полной загрузки ·
  `-pix_fmt yuv420p` — без него Safari и iOS не воспроизведут.
- Рекомендуем: **1280×720**, **24 кадра/с**, **6–10 секунд**; для телефона 720 px по ширине и 4–6 секунд.
  Чем больше кадров, тем плавнее, но тем тяжелее файл: ключевой кадр в каждом кадре весит заметно больше обычного.
- Ориентир по весу: основной файл до 12–15 МБ, мобильный до 5–6 МБ. Тяжелее — поднимите `-crf` (24–28) или
  сократите длительность. Сколько выйдет на самом деле, зависит от картинки: проверьте `ls -lh` после кодирования.
- Если исходный ролик вертикальный, `hero.mp4` лучше сделать горизонтальным: сцена закрывает весь экран, лишнее обрезается.

## Как проверить

1. Файл на месте: `ls -lh public/media/<вариант>/`.
2. Все кадры ключевые: `ffprobe -v error -select_streams v:0 -show_entries frame=pict_type -of csv=p=0 hero.mp4 | sort | uniq -c` — должна быть только строка с `I`.
3. Формат: `ffprobe -v error -show_entries stream=codec_name,pix_fmt,width,height,r_frame_rate -show_entries format=duration,size hero.mp4` — `h264`, `yuv420p`, длительность 6–10 с.
4. `npm run dev`, открыть `/#/<вариант>`: пометка «Здесь будет видео-интерьер» пропала, при скролле hero кадр движется, пояснения появляются на своих отрезках.
5. Скролл медленно и рывком туда-обратно: кадр догоняет с лёгкой инерцией, без дёрганий и зависаний.
6. DevTools → Network: `hero.mp4` отдан со статусом 200/206 (диапазонами).
7. Системная настройка «Уменьшить движение» включена: hero не закрепляется, виден кадр и список пояснений.

## Как это работает

- Постер виден с первого кадра; ролик начинает грузиться после него и появляется поверх, когда готов первый кадр.
- Не нашёлся или не открылся (404, неподдерживаемый формат) — заглушка с пометкой.
- Прогресс скролла плавно сглаживается (rAF), время ролика ставится по кадрам; пока предыдущая перемотка не закончилась,
  новая не начинается.
- Пояснения привязаны к отрезкам прогресса 0–1 и точкам кадра; для скринридера они всегда лежат в DOM упорядоченным списком.

Демо движка (только `npm run dev`): `/#/<вариант>/__scroll-video` — заглушка, ролик и статика на фикстуре.
Фикстуру собирает `node tests/fixtures/scroll-video/generate.mjs` (нужен Chrome).
